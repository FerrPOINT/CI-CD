# ADR-0042: объединение установленного Kubernetes Forge с main

Дата: 2026-10-31. Статус: принято для реализации; квалификация и установка учитываются отдельно.

## Контекст

Работающий Kubernetes Forge собран из `73c72491b5a0e43af532852de3c8bcbec25a581b`.
В GitHub main `5ab203ddf8efac2a796b39765cf0f8b0f196553e` эта история отсутствовала:
42 коммита установленной ветки и 131 коммит main расходились от общего предка.
Установленная ветка содержит image publication, Helm delivery, Kubernetes runner,
подтверждение остановки исполнения и product-local quiescence. Main содержит
новые контракты admission, подтверждение владельца CI и восстановление merge PR.
Обе ветки имеют разные применённые SQLx migrations с номерами 0096–0099.

## Решение

Объединяем истории обычным merge с сохранением обеих линий ancestry. Рабочие
функции Kubernetes остаются в общем Forge. Из main сохраняются проверки прав,
исходные сроки подтверждения доступа и durable merge attempt.

Публикация merge и запуск CI имеют разные подтверждения. Намерение CI сохраняется
в durable attempt вместе с исходным владельцем и выбранной политикой; outbox
создаётся в транзакции подтверждения публикации refs. Диспетчер
использует точный commit и исходного владельца. Перед созданием pipeline заново
проверяются его актуальные права. Потеря ответа не разрешает повторять Git effect.
Неподтверждённая публикация требует штатного readback/recovery PR. Исчерпанная
доставка остаётся в outbox и доступна для явного повторного dispatch.

SQLx ledger и checksums уже применённых migrations не меняются. Пакет содержит
две явно выбираемые истории:

| Установка | Каталог | Переход |
| --- | --- | --- |
| Main / новая | `/app/migrations` | исходные main 0001–0107, затем native 0108–0111 |
| Установленная native v1 | `/app/migrations-kubernetes-v1` | исходные общие 0001–0095 и native 0096–0099, затем main 0100–0111 |

Исторические пропуски номеров сохраняются. Обе истории сходятся перед общей
0112; дальнейшие migrations имеют одинаковые номера и SQL bytes.
`scripts/migration_lineages.py` проверяет SHA-384 исторических файлов по manifest
и собирает native projection. Явные CRLF из `.gitattributes` входят в checksum.
Автоматическое определение истории и редактирование `_sqlx_migrations` запрещены.

## Обновление и откат

До изменения существующей БД сохранить backup и проверить восстановление на
изолированном PostgreSQL. По фактическому ledger выбрать каталог через
`CICD_MIGRATIONS_DIR`, проверить dry-run и выполнить owner migration. Неверный
каталог должен завершаться checksum mismatch без изменения применённой истории.
Сам dry-run показывает план и не является подтверждением успешной миграции.
После применения проверить историю, сохранность данных и работу API/runner.

Откат приложения использует совместимый квалифицированный binary; новые строки
и SQLx ledger сохраняются. Down migrations, подмена checksum и переприсвоение
native номеров main не используются. Backup/recovery gate и установка имеют
собственные результаты; объединение исходников их не заменяет.

## Последствия

Одно приложение поддерживает обе существующие установки. Поставка должна
сохранять выбранный каталог при последующих обновлениях. Отдельные проверки
покрывают fresh main и populated native upgrade, отказ неверной истории,
приёмку Kubernetes и Compose, права и восстановление merge/outbox.
