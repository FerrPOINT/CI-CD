# ADR-0040: несколько подключений синхронизации репозитория

Принято, 2026-10-28. Заменяет ограничение одним подключением.

Hosted-репозиторий допускает несколько независимых HTTPS-подключений, в том
числе одновременно GitHub.com и собственный GitLab. У каждого стабильный UUID,
credential, версия настроек, направление, режим запуска, dirty-флаг, расписание
и история. Отключение или замена токена одного подключения не затрагивает другие.
История сохраняет снимок настроек и не переносится при изменении endpoint.

Аддитивная миграция 0106 сохраняет прежнему подключению UUID репозитория,
дополняет историю и original-key readback идентификатором подключения. Существующие
версии, ciphertext, SHA, результаты и ключи операций сохраняются. Составные FK
не позволяют связать запуск или команду с подключением чужого репозитория.
Released migrations не меняются.

HTTP-пути сохраняются. Необязательный query `connection_id` выбирает точное
подключение; без него используется только прежний UUID, без выбора первой строки.
PUT с новым клиентским UUID и expected_version=0 создаёт подключение. Повтор
сохраняет тот же UUID и Idempotency-Key, в том числе после потерянного ответа.
Ключ повторно не используется между подключениями. Общий список возвращает
подключения отдельными строками; repository_id фильтруется до total/page.
Права и archive admission проверяются по UUID репозитория, а не подключения.

Одно подключение допускает один активный запуск, включая очередь. Несколько
подключений могут ждать одновременно; running/stopping/reconciling допускаются
только у одного запуска репозитория. SQL claim и прежний межпроцессный Git guard
сериализуют запись и recovery. Истечение lease не отменяет guard живого Git.
Выборка worker исключает queued-соседей незавершённого writer и выбирает только
одного кандидата каждого репозитория до общего лимита страницы. Возраст queued
запуска не даёт ему вытеснить recovery; большая очередь подключений одного
репозитория не занимает всю страницу независимых исполнений.
Принятые входящие изменения сигнализируют всем automatic-подключениям; ручные
не запускаются. Повторы объединяются dirty-флагами; равные refs дают no-op.
Алгоритм fast-forward, защита веток и запрет распространения удаления сохраняются.

UI переиспользует общий список и прежнюю форму. Контекст репозитория открывает
его подключения; строка открывает конкретную форму и историю. ID хранится в URL
и query-cache keys, токены и черновики — только в памяти. Прежние ссылки с явной
вкладкой открывают исходное подключение.

Поставка требует проверки populated migration и согласованного обновления API
и worker. Старые бинарники с singleton SQL не совместимы с новой схемой; перед
миграцией исполнение останавливается, после неё запускается новый cohort.
Миграция не включает подключения и не меняет worker feature flag. Установка
runtime — отдельная операция; откат сохраняет БД и требует совместимого бинарника,
down-migration не выполняется.
