# ADR-0047: PR задачи и замечания Reviewer

Статус: принято в исходниках, 2026-11-08. Установка выполняется отдельно.

## Решение

Новый PR содержит обязательный `primary_task: TaskRef`. Forge проверяет Task
существующим namespace-reader Tracker и сохраняет основную задачу вместе с уже
существующей `pull_task_links` в одной транзакции с номером PR. Дополнительные
связи разрешены. Основная задача одна, повтор выбора другой основной запрещён.
Доступ Reviewer к самой Task, обсуждению и вложениям остаётся существующим.
Машинные PR-команды подключены к существующему Central service-account адаптеру:
ci-cd:read/write и фактическое членство проекта. Для записи те же membership/user
проверяются и удерживаются до COMMIT с исходным request deadline. Human Space
permit не выдаётся машине; новые grants, credentials и Task ACL не создаются.
Детали готовых pipeline, jobs, страниц логов и artifacts читаются по тому же
членству проекта, включая проверки другого агента. Владение workspace не требуется
для чтения CI; операции workspace сохраняют существующие проверки назначения.

Каталог `GET /api/v1/task-pulls` выбирает все связанные PR, включая closed/merged,
после обычного read admission и ограничения scoped project. CLI обходит страницы;
Developer не формирует отдельный список для ревью. Перед отчётом Reviewer повторно
сверяет состав PR и base/head SHA и изучает изменения. Фонового наблюдателя нет.

`review-context` задаёт точные base/head/merge-base. `patch` передаёт полный diff
потоком без ограничения preview 512 KiB; `checks` читает готовые pipeline receipts
для проверяемого head SHA со страницами. Источники, job details и логи читаются
существующими API. Reviewer не запускает pipeline, тесты, build или workspace.
Карточка PR показывает готовые проверки закреплённого head SHA и позволяет
скачать полный patch через существующий авторизованный клиент файлов.

Замечания принадлежат Forge и существующей карточке PR. Общий комментарий либо
anchor `{path, side: old|new, line}` сохраняются с автором, важностью, текстом,
base/head SHA и operation UUID. Anchor проверяется по Git diff этих commit;
удалённая строка относится к old. Комментарий неизменяем. Пара PR/автор/operation
уникальна: одинаковый повтор возвращает сохранённое, другое тело даёт 409.
Повтор сохранённой операции работает после изменения head и restart. Новая запись
со старыми SHA даёт 409. Старые комментарии не переносятся на новую версию.

## Миграция

Обязательный `primary_task` — намеренно несовместимое изменение создания PR.
UI и CLI переходят на новый DTO вместе с сервером; старый клиент получает ошибку
валидации. Режима создания PR без задачи и автоматического выбора Task нет.

0116 выбирает основную Task только при одной существующей подтверждённой связи.
История без связи или с несколькими связями сохраняется с null primary, пока
владелец не подтвердит соответствие. Новая запись без primary запрещена также
отложенным ограничением БД; составная FK требует реальную связь в той же транзакции.

`scripts/migrate_pull_tasks.py --output <new.json>` инвентаризирует остаток без
записи. Оператор заполняет `confirmed_task` и `reason`; `--apply <json>` проверяет
идентичность/версию PR, выбирает primary через существующий task-link API и читает
результат. При потере ответа выполняется readback. Названия, близость дат и первый
найденный Task не являются доказательством. Существующая подтверждённая связь
выбирается без повторного чтения удалённой ветки. Для новой связи нужен доступный
подтверждённый source commit; недоступная история требует отдельного разбора.
На установленном стенде инвентаризация и применение этой доработкой не выполнялись.
При установке Forge/UI/CLI и terminal-контракты Tracker/Fleet обновляются
согласованно. Выполняемое Reviewer-назначение со старым каталогом сначала
завершают или останавливают штатной операцией: миграция Workflow сохраняет его
снимок и не перепривязывает историю к новым инструкциям. Общий Fleet consumer
для этого не отключается.

## Граница завершения

Workflow принимает выполненное ревью с фактическим approved/rework, после чего
агент публикует обычный итоговый комментарий Task и существующий typed proposal.
Fleet завершает native run и вызывает прежний Tracker Complete. Tracker сохраняет
вердикт и освобождает назначение/lease/binding; Review остаётся Completed/Terminal
с `review_completed`. Обнаруженные дефекты не означают сбой агента. Завершение
Workflow не является одобрением кода. Общий Fleet consumer продолжает работать.

Автоматические Developer ↔ Reviewer ↔ Tester циклы — следующий этап. Сейчас
завершение Review не переводит Task, не создаёт очередь и не запускает следующую
роль. Не добавляются сервис ревью, отдельный runner или механизм исполнения.
