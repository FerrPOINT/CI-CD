# ADR-0045: общее расписание внешней синхронизации

Статус: принято для source-кандидата; production-приёмка отдельно.

Расписание принадлежит Forge, который владеет подключениями и исполнением.
Admin не хранит копию. Период и запуск после изменений общие для всех
автоматических подключений; ветка остаётся настройкой подключения.
Используется существующий supervisor, очередь и durable capacity: второго
планировщика, cron или сервиса нет. Конкурентность задаётся оператором.

Одна append-only таблица содержит версии политики и original-key readback.
Пустая история сохраняет прежние env defaults (300 секунд, on_change=true).
После явного сохранения БД имеет приоритет. Сохранение сериализовано CAS и общим
advisory lock, проверяет подтверждённого human admin и пишет identity-fenced audit.
Роль повторно проверяется в транзакции; PAT и machine credentials запрещены.
Shared lock worker/connection-save исключает создание срока со старой политикой
после её изменения. Действующие jobs не отменяются, ручные runs не сдвигают часы.
Пересчёт сроков использует общий допуск планировщика: архивные, отключённые,
замороженные и недоступные подключения не изменяются. Их состояние не блокирует
сохранение общей политики для остальных подключений.

UI находится в Forge → «Конфигурация сервера». Неопределённый результат сохраняет
исходный UUID/тело команды для проверки без двойного сохранения; конфликт требует
загрузки актуальной версии. Устаревший replay не выдаётся за текущую конфигурацию.

Семантика одинакова в Docker/Compose и Kubernetes: адаптеру установки принадлежат
ENABLED/CONCURRENCY, приложению — сохранённая политика. Миграция 0114 аддитивна;
не переписывает прежние migrations/checksums или существующие данные.

Для отката reader должен понимать сохранённое поле branch в connection/run JSON.
Старый worker не читает политику из БД: смешивать его с новым API нельзя. Требуется
согласованный откат API/worker/UI с совместимыми branch reader и env-периодом,
сохранение полной истории и проверка на копии данных. Возврат старой БД поверх
новых записей или удаление полей из immutable истории не являются откатом.
