# ADR-0041: допуск синхронизации и владелец фонового CI

Статус: принято, source-кандидат. Дополняет ADR-0040; runtime отдельно.

HTTP-чтение синхронизаций человека использует тот же подтверждённый общий
Space admission, что каталог и Git-браузер. Фильтр разрешённых групп применяется
до count/page; пустой набор не становится unrestricted. Общая видимость заменяет
прежнее read membership, сохраняя scopes и project binding токена. Запись
дополнительно требует native write role, действующую проекцию и lifecycle lease;
исходный proof ограничивает SQL commit и ответ. SAT использует прежний отдельный
допуск по проекту/scopes и не получает human authority.

Планировщик, проверка исполнения и отображение паузы используют effective
lifecycle V2/V1. Проверка берёт существующие share locks проекций: архивация
не может изменить решение между выбором подключения и постановкой запуска.
Архивное подключение сохраняет настройки и историю, не блокируя соседние задачи.
Подключения с frozen identity исключаются до лимита очереди; повторный отказ
DB admission изолируется savepoint подключения и не откатывает здоровую работу.

Уже отключённое подключение с незавершённым запуском допускает замену токена
только с полностью прежними настройками. Версия растёт, cancel_requested
сохраняется. Исходные SHA, endpoint, owner и намерение запуска неизменны;
восстановление наблюдает фактические refs и не повторяет неизвестный push.
Первичное отключение работающего подключения не совмещается со сменой токена.

Миграция 0107 добавляет private owner_subject подключения и снимка запуска.
Обычное сохранение записывает подтверждённого central human owner запроса;
технический вызов не подставляет администратора. Отключение и reauthentication
незавершённого запуска сохраняют владельца. При новом запуске owner копируется
атомарно с версией настроек. CI outbox использует существующий with_saved:
перед каждой доставкой заново проверяются текущие права владельца в Auth.
Точный SHA и ключ идемпотентности CI сохраняются. Отзыв доступа не теряет событие.
CI outbox выбирается по времени следующей попытки до лимита: медленные повторы
старых запусков не вытесняют ещё не обработанные события новых запусков.

При обязательной application policy старые/машинные подключения без human owner
не могут создавать обычный CI: pending-события остаются до разбора владельцем.
Настройки можно заново сохранить подтверждённым человеком для будущих запусков;
старому событию новый владелец не приписывается. При выключенной политике прежний
режим сохраняется. Новые ссылки участвуют в identity deletion inventory/fence.
API DTO и адреса не меняются; owner не является credential или cached grant.

API и worker поставляются согласованно: старый sync writer не сохраняет владельца
нового намерения. Не обслуживать запись старым API одновременно с новым worker;
на время замены исполнение остановлено. Перед включением обязательной политики
нужна явная привязка старых автоматизаций подтверждённым владельцем. Исторические
непривязанные события остаются pending, без назначения чужой identity задним числом.
