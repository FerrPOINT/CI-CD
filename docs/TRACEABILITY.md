# Матрица трассируемости требований (RTM) — Forge CI/CD

Этот документ связывает утверждённые требования из [PRODUCT_REQUIREMENTS](PRODUCT_REQUIREMENTS.md) с нормативными контрактами, реализационными границами, проверками и evidence. Статус означает фактическую зрелость capability по таксономии продукта; он не выводится из наличия страницы, DTO или настройки. Уровни тестирования, окружения и критерии выхода описаны в `docs/TEST_PLAN.md`.

**Обозначения evidence:** `CI current` — действующий `.github/workflows/ci.yml`; `CI target` — обязательный gate из [DEVELOPMENT_GUIDE](DEVELOPMENT_GUIDE.md#ci-гейты); `screens` — [реестр скриншотов](assets/screens/manifest.md). Для `Target approved` в колонках «Проверка» и «Evidence» указано условие, после которого статус может быть повышен.

## 3. Правила поддержки RTM

1. Новый capability или ключевой NFR получает уникальный `REQ-ID` **до** начала реализации. Идентификатор не переиспользуется после удаления или отмены требования.
2. Одновременно обновляются `docs/PRODUCT_REQUIREMENTS.md` и эта RTM: краткое имя, owner-контракт/архитектура, проверка, evidence и фактический статус.
3. `Current verified` допускается только с воспроизводимой проверкой и ссылкой на evidence; настройка без execution/delivery остаётся `Configuration only`.
4. Для каждого `Target approved` заранее указываются конкретные contract test и CI gate, которые требуются для перевода в `Current verified`.
5. При изменении контракта сначала обновляется его нормативный owner, затем RTM и производные документы в соответствии с [DOCUMENTATION GOVERNANCE](DOCUMENTATION_GOVERNANCE.md#изменение-документации).

## 4. Чек-лист PR

PR, который добавляет или меняет capability, NFR, публичный контракт либо status, **не мержится**, пока не выполнены все применимые пункты:

- [ ] Требованию назначен новый или существующий `REQ-ID` в `docs/PRODUCT_REQUIREMENTS.md` до реализации.
- [ ] В этой RTM есть строка с контрактом/архитектурой, уровнем проверки, evidence и корректным статусом.
- [ ] Для `Target approved` определены contract test и CI gate; для `Current verified` приложено воспроизводимое evidence.
- [ ] Изменённые tests, CI gates, screenshots или operational evidence актуализированы и прошли проверку.
- [ ] Выполнен `python3 scripts/verify_docs.py --all` и применимые current/target quality gates из [DEVELOPMENT_GUIDE](DEVELOPMENT_GUIDE.md#ci-гейты).
