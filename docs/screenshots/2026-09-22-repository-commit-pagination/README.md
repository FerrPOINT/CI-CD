# Repository commit pagination QA

Проверка завершена 2026-09-23 в Chromium на production-сборке Dashboard.
Использованы реальные Central Auth и platform shell; только ответы read-only Git
маршрутов для `qa-history` заменены детерминированной историей из 51 коммита.
Backend и рабочие данные не изменялись.

Проверено:

- первая страница запрашивает `limit=26&offset=0` и показывает 25 коммитов;
- вторая и третья страницы используют `offset=25` и `offset=50`, поэтому 51-й
  коммит доступен пользователю;
- выбранная страница сохраняется в `commitPage` URL;
- переход к более ранним коммитам выполняется клавишей Enter;
- устойчивый `503` проходит автоматические повторы, показывает локальную ошибку,
  сохраняет возможность вернуться к новым коммитам и восстанавливается ручным
  повтором;
- длинные subject и author корректно переносятся на mobile;
- размеры `375`, `768`, `1280`, `1920`, `2560` проверены в темах
  `light`, `gray`, `dark`, всего 15 состояний;
- во всех состояниях: 0 horizontal overflow, малых интерактивных целей,
  неожиданных вложенных scroller, неожиданных runtime/network errors и
  serious/critical axe findings.

Артефакты:

- `history-375-light.png` — первая страница и mobile pagination;
- `history-1920-gray.png` — плотная desktop-история в серой теме;
- `history-2560-dark.png` — wide desktop в тёмной теме;
- `desktop-page-3-light.png` — прямой доступ к 51-му коммиту;
- `desktop-page-error.png` — terminal error с повтором и возвратом;
- `qa-report.json` — запросы и автоматические проверки матрицы.
