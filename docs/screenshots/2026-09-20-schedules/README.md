# Проверка UI расписаний проекта

Снимки получены в Chromium на настоящем компоненте Schedules с общей темой и шириной рабочей области, как в app shell. Временный стенд подставил 25 синтетических записей: включённые, выключенные, ошибочное legacy-расписание и длинные cron/ref. GET был замокирован; DELETE в сценариях ошибки возвращал намеренный 500. Реальные расписания и проекты не менялись.

Проверены ширины 320, 375, 768, 1280, 1920 и 2560 px в тёмной теме; на 375 px также светлая и серая темы. Отдельно проверены открытые формы создания и редактирования, ошибка удаления и диалог на 320/375 px. После доработки общего ConfirmDialog четыре состояния ошибки удаления проверены повторно: название записи сохраняется, ошибка объявляется через alert. Во всех 14 итоговых состояниях нет горизонтального переполнения, видимых целей меньше 40 px и серьёзных/критических нарушений axe WCAG 2.1 A/AA. Детальные результаты: `qa.json`.

Это браузерная проверка компонента с подменёнными ответами, а не приёмка на развёрнутом API и SSO shell. Живая интеграционная проверка остаётся условием релиза.
